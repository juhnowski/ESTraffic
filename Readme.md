# Запуск
Войдите в Nix-окружение проекта:
```bash
nix develop
```
Запустите Elasticsearch/OpenSearch в фоновом режиме:
```bash
start-es
```
Дайте процессу секунд 15 на запуск JVM и инициализацию структуры.
Запустите генерацию поисковых индексов и экспорт данных:
```bash
run-bench
```

# Особенности анализа файлов Apache Lucene (Elasticsearch)
Полученные файлы с расширением .cfs.raw или .fdt.raw в папке ./es_bench_blocks/ — это бинарные слепки документов, оптимизированные под полнотекстовый поиск.

- Потоковая блочная структура: Lucene группирует документы в блоки (обычно по 16 384 документа или кратными определенному объему). Внутри файла данные сильно реорганизованы: строки сжимаются целыми пачками.
- Стресс-тест для дедупликации: Поскольку Lucene по умолчанию сжимает свои блоки с помощью LZ4, этот стенд — идеальный индикатор качества постдедуп алгоритмов. Если алгоритм поверх сжатых файлов Lucene в сценарии 1_duplicates сможет найти дополнительные совпадения (благодаря глобальной кросс-блочной дедупликации, которой нет в локальном LZ4), значит, мы спроектировали очень сильный алгоритм со скользящим окном.

# Особенности
Стенд для Elasticsearch (или его современного open-source форка OpenSearch, который проще разворачивать в легковесных средах) ставит перед алгоритмом дедупликации очень интересную задачу.
Elasticsearch построен на базе поискового движка Apache Lucene. Данные хранятся в виде неизменяемых сегментов (Segments), которые архитектурно напоминают LSM-дерево. При записи документа он попадает в буфер, а затем сбрасывается на диск при операции refresh в виде набора файлов. Основной бинарный трафик документов лежит в файлах с расширением .fdt (Field Data) и .fdm (Field Metadata).
По умолчанию Lucene агрессивно сжимает эти файлы встроенным алгоритмом LZ4. Чтобы протестировать постдедуп алгоритмы, мы переключим индекс в специальный режим best_compression (в последних версиях Lucene это позволяет использовать кастомные кодеки, либо мы сгенерируем плотные текстовые повторы, которые пробивают окно сжатия LZ4, чтобы алгоритм мог соревноваться со встроенным).
